## 4. 배포 전 사람이 직접 해야 하는 것

코드로 끝낼 수 없는 항목만. 절차는 [deployment.md](./deployment.md) 참조.

1. **운영 DB 분리** — 개발/테스트 DB와 다른 Neon 브랜치 또는 인스턴스를 쓴다. 테스트가 실데이터를 건드리지 않도록.
2. **시크릿 발급** — `SECRET_KEY`는 운영용으로 새로 생성한다 (개발값 재사용 금지).
3. **쿠키 설정** — cross-site 배포(프런트/백엔드 도메인이 다름)면 `COOKIE_SECURE=true`, `COOKIE_SAMESITE=none`.
4. **CORS** — `FRONTEND_ORIGIN`에 실제 프런트 URL을 넣는다.
5. **실기기 확인** — 에뮬레이터가 대신할 수 없는 항목은 §5.

## 5. 실기기에서 확인할 것

에뮬레이터로는 신뢰할 수 없어 QA 4단계에서 사람 몫으로 남긴 항목.

- iOS Safari URL바 접힘/펼침 중 별밭이 튀지 않는지
- 한 손 엄지로 책 상세의 진도/전달 버튼에 닿는지 (현재 1.08–1.18 화면 위치)
- 소프트 키보드가 올라온 상태에서 진도 · 한줄평 입력이 가려지지 않는지
- 노치/홈 인디케이터 영역 (현재 `viewport-fit=cover` 미사용, 브라우저 자동 인셋)
- Android 중저가 기기에서 별밭 켠 채 수 분 사용 시 스크롤 부드러움 · 발열
- 탭 후 `:hover` 고착 여부 (Cover/Bookshelf에서 탭 → 뒤로가기)
- 책장 가장자리 스와이프가 브라우저 뒤로가기를 유발하지 않는지
- VoiceOver / TalkBack으로 별점 · 진행률 읽기

## 6. 남은 known issue

- **표지 이미지 도입 후에도 Hero 목록(모바일)에는 표지가 없다** — 모바일 Hero에 표지 노출면이 원래 없기 때문. §2 결정 참조.
- **`cover_url`은 프런트에서만 검증한다** — 절대 http(s)가 아니면 렌더하지 않고 그라디언트로 떨어진다. 백엔드는 문자열 길이(500)만 제한한다.
- **표지는 `next/image`를 쓰지 않는다** — 임의 호스트를 허용하려면 `remotePatterns` 와일드카드가 필요하고, 그 경우 서버가 임의 URL을 대신 fetch하는 오픈 이미지 프록시가 된다. plain `<img>` + lazy 로딩으로 처리.
- **Bookshelf 툴팁이 `.bc-case`의 `overflow:hidden`에 잘린다** — 데스크톱 전용 이슈.
- **Playwright `reuseExistingServer`** — 로컬에 `next start`가 떠 있으면 빌드를 건너뛰고 옛 번들을 테스트한다. 소스 수정 후에는 `:3000`을 정리하고 돌릴 것.
- **Neon 개발 DB가 느릴 때가 있다** — backend pytest가 5분에서 25분 이상으로 널뛴 적이 있다. 코드 신호가 아니라 DB 응답 지연.
